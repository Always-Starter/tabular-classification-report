# Tabular Classification Report

Take a training dataset path as the starting input. Prefer a target explicitly supplied by the user or authoritative task/dataset metadata. If none is supplied, inspect training only and propose a possible classification target. A single conventional target name with classification-compatible values may be used provisionally so the default run can continue; explain the evidence and uncertainty. If evidence is ambiguous or weak, show candidates and ask. A guessed target is not confirmed task semantics: never infer it solely from column order, cardinality, filename, association or prior examples. Optional inputs are a held-out path, Excel worksheet (default `Data`), output folder, error costs and report metadata. CSV/TSV/XLSX are supported; legacy XLS requires `xlrd`. A separate test file is optional: nested CV can support a development-only report.

Use the installed skill directory for scripts and references. Save each experiment in a new output folder outside the skill and source data. Check Python dependencies from `requirements.txt` before running. Package fixtures are synthetic software tests, not course data or a model-selection prescription.

For every material choice, record **Observation → Decision → Rationale → Human-review point**. Ground decisions in the supplied training data. Do not infer customer churn, business meanings or label meanings from an example, filename or prior demonstration.

Use **English by default** for progress updates, review questions, and generated report narrative. If the user's current request clearly uses another language, respond in that language; an explicit language preference takes precedence. When a request contains only paths, commands, or otherwise gives no clear language signal, use English. Follow a later language switch for subsequent messages. Do not carry an earlier conversation language into a new English-language request, and do not translate dataset column names or observed label values.

## Invariants

- Keep all held-out file contents sealed through diagnosis, planning and development; do not profile test predictors or labels. No test-based model revisions.
- Fit learned imputation, encoding, scaling, selection and transformations inside training folds. Choose grouped or temporal validation when observations are dependent.
- Exclude missing targets from supervised fitting/scoring; report counts. Predict unlabelled rows without claiming accuracy.
- Review identifiers, duplicate entities, target proxies and feature availability. Association alone does not prove leakage or justify deletion; unusual/outlying values are not automatically errors.
- If an independent held-out file is supplied, freeze every selected complete fitted pipeline before held-out access. In the default end-to-end run, proceed to one held-out evaluation without a routine Model Lock approval pause. If the user explicitly requested staged review, freeze with `--require-human-approval` and wait for their approval of the exact displayed digest. Never create a human approval on the user's behalf. Do not require a holdout or Model Lock for a training-only report.
- The receipt and hashes enforce normal workflow checks, not security against someone deliberately editing/deleting the files. Preserve them. Never rerun or remove a receipt to improve test performance.

## Execution and review

By default, complete the requested analysis in one run: training diagnosis, data-specific plan, nested-CV development, optional frozen one-time held-out evaluation, verification and a draft report. Do not ask the user to select a mode or approve routine intermediate decisions. Explain material decisions and review points in the deliverables. An explicit request for "continuous execution" is equivalent to this default.

If the user explicitly requests **staged review**, a checkpoint limit, or a pause before held-out evaluation, honour that request. In staged review, show the diagnosis after Checkpoint 1, the plan after Checkpoint 2, and training results and Model Lock after Checkpoint 3. Stop at each boundary and wait for the user's response. Whenever the user requests approval before testing, freeze with `--require-human-approval`, show the exact digest, and obtain explicit approval before evaluation. Keep the selected mode for the run; do not ask again at every checkpoint.

System/tool permission to read a file is separate from a workflow approval. A supplied path does not bypass filesystem permissions: request access when the host requires it, and resume only after access is granted. If a supplied held-out path is accessible, the default run may evaluate it once after freezing without asking for another Model Lock approval.

Stop and ask only when target inference is unresolved or ambiguous, an inaccessible file, unresolved high-risk leakage/provenance issue, unsupported data structure, or other blocking problem could invalidate the experiment. Do not treat unknown business meaning, error costs or report identity metadata alone as a reason to halt; disclose the limitation and keep the report a draft. Honour later requests to stop or switch modes. Never infer user consent to read a file that the host has not authorized.

At a requested review pause, present actual results and artifact links. For each material decision, show what the AI decided, why, what the human should review, and a reasonable alternative worth challenging. State exactly what approval would start next. Ask only for information the user may know; allow “unknown” and disclose resulting assumptions or limitations. Do not treat silence as approval or claim a manual check the user has not performed.

## Workflow and routing

Read [checkpoint-workflow.md](references/checkpoint-workflow.md) for commands and apply the default end-to-end or explicitly requested staged flow.

**Preflight (before Checkpoint 1): resolve target and validate input.** Run `scripts/inspect_training_schema.py` on training only, with `--target` only if the user or authoritative metadata supplied it. If it returns `provisionally_inferred`, disclose the suggested column, candidate alternatives, naming/cardinality evidence, and that semantics remain unconfirmed; proceed only if no visible task context contradicts it. Record the target's inferred source in the decision log and draft report, with a human-review point to confirm it. If unresolved, show candidates, ask and stop. If a supplied column is absent, show the actual columns and stop rather than substituting another.

1. **Diagnose training data.** Once resolved, run `scripts/diagnose_training.py` with both `--train` and explicit `--target`. Inspect missingness, class balance, duplicates, numeric ranges, cardinality and descriptive associations. Explain domain uncertainty and candidate leakage. Neither CLI has a test-path option.
2. **Propose the plan.** Read [modelling-decisions.md](references/modelling-decisions.md) and [model-plan-schema.md](references/model-plan-schema.md). Select appropriate candidate classifier families for empirical comparison, not a presumed winner: two by default, a third only for a distinct training-evidence-based question. Record the registry snapshot and whether the shortlist was training-driven, user-supplied or rule-based; do not imply an exhaustive search over all algorithms. For each candidate, explain expected strength, known limitation, grid rationale and stopping rule. Record target/positive-class semantics, error costs, row dependence and material feature provenance as confirmed or unknown. Decide per-model preprocessing, optional feature handling, a predeclared primary metric and interpretive secondary metrics, dependency-safe splits, bounded grids and sensitivities only for material uncertainty. Write a schema-v3 JSON plan and validate with `scripts/validate_plan.py`. No fitting at this stage.
3. **Develop; lock if holdout exists.** Run `scripts/run_nested_cv.py`: inner CV tunes, outer CV evaluates the tuned procedure. Preserve candidate-level inner scores for every outer search and the final full-training search. Outer results must not drive grid expansion, family/preprocessing redesign or a new primary metric within the same evaluation claim; a later redesign is a new development iteration. Stop tuning after the prespecified bounded inner search. Review fold variability, near-ties, warnings, sensitivity evidence and numeric-grid boundary flags without automatically expanding the search. Record the variant/model selection rule and final refit evidence. If an independent holdout exists, select a complete variant, write the review JSON, read [model-lock.md](references/model-lock.md), then run `scripts/freeze_model_lock.py` (add `--require-human-approval` only when the user requested approval before testing). Save all frozen pipelines and the exact digest.
4. **Optional one-time holdout, verification and report.** In the default run, call `scripts/evaluate_holdout.py` once after freezing. When the user requested approval before testing, wait for approval of the exact lock, record it with `scripts/approve_model_lock.py`, then evaluate once. Verify saved predictions with `scripts/verify_results.py` without reopening test data. With no holdout, use nested-CV development evidence for the report. Never revise model decisions using held-out results.

For reporting (including when there is no test file), read [report-template.md](references/report-template.md). Write evidence-based narrative JSON, then run `scripts/generate_report.py`. It generates Markdown, a PDF with two main pages plus Reflection, and an evidence manifest. Visually inspect the PDF. Numerical tables come from verified saved results; check that narrative claims agree with them. Keep unknown metadata and unperformed human actions explicit and mark the report as a draft.

For a requested audit, run `scripts/audit_training_run.py` against saved training results and optionally the Model Lock. The audit command has no held-out path and must not reconstruct missing evidence by refitting. Mark absent legacy evidence and unresolved semantics as unknown.

## Capability boundaries

The packaged runner supports binary/multiclass targets, seven established classifier families including guarded SVM support, per-model imputation/encoding/scaling, stratified/grouped/forward-time nested CV, and declared feature/preprocessing/model-parameter/threshold sensitivity variants. See the plan reference for exact options and budget limits. It does not automatically solve every possible tabular problem: multilabel targets, custom feature engineering, large sparse encodings or scalable kernel approximations need an explicit extension.

When the dataset needs an unsupported method, explain the limitation and extend the reusable plan/pipeline/scoring implementation with a focused synthetic test **before development**, if authorized by the analysis task. Do not silently choose a supported but inappropriate method, improvise an evaluator that bypasses the lock, or claim universal support. Changing code after locking invalidates that lock; after test access, disclose the limitation without retuning.

The assignment explicitly requires a reusable skill for tabular classification, dataset-path input, AI-selected models and preprocessing, automated PDF reporting against Variant 1's criteria, model/version and interface metadata, GitHub submission, and Reflection. Variant 1 asks for two models; Variant 2 does not explicitly impose an exact model count. This runner's two-or-three-model bound (two by default), target-resolution gate, optional staged review, nested CV, sensitivity framework, bounded search, optional Model Lock, sealed holdout, hashes, receipts, verification and evidence manifest are skill enhancements, not quoted grading requirements. Preserve them while optimising for justified, reproducible, data-specific and reviewable decisions rather than maximum accuracy. Include full name, matric number, `IN6227-Assignment-1`, `Variant-2`, verifiable LLM model/version, interface and GitHub URL in the report. The main PDF is at most two pages; Reflection follows outside that limit. Draft Reflection must mark unperformed human review, challenge, approval and manual verification as pending; never invent them.
