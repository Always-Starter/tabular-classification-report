# Dataset-specific decisions

For each material item record observation, decision, rationale and human-review point before fitting. Dataset paths and column names convey no reliable business semantics. The plan chooses candidates for empirical comparison, not a winner before evaluation.

- **Target and metrics:** Identify the target from task semantics or authoritative metadata, never a statistical guess. Confirm label meaning and binary positive class. Choose the primary metric **before fitting** from task objective, class balance, known error costs, binary/multiclass setting and whether ranking, hard labels or probability quality matters. Record Observation → Metric → Rationale; it governs inner-CV tuning and the prespecified comparison. Secondary metrics interpret the error profile rather than replace the primary after seeing results. Preserve labels as strings (including numeric-looking labels). Macro metrics help multiclass/minority visibility; binary precision/recall/F1 suit corresponding error trade-offs; accuracy, average precision or log loss need their own justification. Average precision is not trapezoidal PR-AUC. Unknown costs are a limitation. Undefined metrics receive null with a reason, not invented zeroes.
- **Preprocessing:** Use training-specific evidence: missingness pattern, skew/outliers, model scaling needs, categorical cardinality/sparsity, leakage risk and uncertain feature semantics. Choose allowed imputation, encoding, scaling, transformation and indicators per model; do not apply one fixed recipe. Fit learned steps inside each training fold. Ordinal encoding imposes artificial order on nominal categories; log1p needs values > -1 and an interpretable reason. No automatic outlier removal or correlation-based deletion. Record Observation → Decision → Rationale → Human-review point for each material choice.
- **Features and dependence:** Record selected columns and explicit reasons for exclusions. Feature selection/engineering is optional: if no supported transformation is needed, say so rather than inventing one. Detecting an outlier is not evidence to delete it. Consider entity IDs, duplicate records, timestamp ordering, target proxies and information unavailable at prediction time; association alone does not establish leakage. Do not use shuffled CV for repeated entities or temporal forecasting. Group/time columns are excluded as predictors by the bundled runner. Time gaps count distinct timestamps, not rows or calendar days. For more complex embargoes, extend and test the splitter before development.
- **Model count and contrast:** Choose two complementary classifiers by default. Add a third only if the diagnosis motivates a distinct question that the first pair cannot address, within the compute and two-page report budget. This is a skill design choice, not a Variant 2 mandate. For each candidate record Observation → Selected classifier → Rationale → Expected strength → Known limitation → Human-review point; the plan's rationale field may include the strength and limitation. Discuss only materially relevant dimensions such as sample size, feature types/dimensionality, imbalance, plausible nonlinearity/interactions, outliers, interpretability, dependence and compute. The six available families are logistic regression, random forest, extra trees, decision tree, KNN and Gaussian Naive Bayes, not a required pair/trio.
- **Validation and tuning:** Nested CV is this skill's methodology, not an explicit course requirement. Inner CV selects hyperparameters/configurations; outer folds evaluate the tuned procedure. Outer scores do not justify expanding grids, changing family/preprocessing/primary metric and then claiming the same outer estimate is independent. Such redesign is a new development iteration with its own selection uncertainty. The final inner search determines the full-training artifact. Prespecify bounded grids and fit budget; tuning stops after the inner search is exhausted, not when an arbitrary score is reached. A selected numeric-grid edge is disclosed as untested-direction uncertainty, not automatically expanded. Fold SD is descriptive, not a confidence interval. With time CV report OOF coverage. Declared sensitivity selection still adds optimism.
- **Sensitivity:** Use only for a material uncertainty. Empty `sensitivities` is valid with a recorded explanation. Alternative configurations run against the same folds and labels. Select one complete variant before locking. Do not choose sensitivities after viewing test results or combine fragments of variants without another train-only experiment.
- **Comparison and stopping:** Compare primary scores on shared outer splits, alongside fold variability, consistency, secondary metrics, complexity and limitations. Distinguish “numerically higher” from “meaningfully better.” For a near-tie, state uncertainty and choose a required preferred configuration using documented interpretability, stability and compute considerations; if those are also indistinguishable, use the predeclared plan order as a deterministic last resort. Do not invent a universal numerical tie threshold. Convergence warnings fail the run; fix settings only using training evidence. Other warnings require review. No automatic adaptive refinement is bundled.
