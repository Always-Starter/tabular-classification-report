# Dataset-specific decisions

For each item record observation, decision, rationale and human-review point before fitting. Dataset paths and column names convey no reliable business semantics.

- **Target and metrics:** Confirm label meaning and binary positive class. Preserve labels as strings (including numeric-looking labels). Use macro metrics for multiclass/minority-class visibility, binary precision/recall/F1 when corresponding error trade-offs matter, accuracy when justified, average precision for positive-class ranking, or log loss for probability quality. Average precision is not trapezoidal PR-AUC; report its actual name. Unknown error costs are a limitation. Binary zero denominators produce null with a reason; macro/weighted scores use per-class zero-division convention 0. Explain undefined metrics rather than treating them as observed failures.
- **Preprocessing:** Choose imputation rather than assuming missing rows are disposable. Median versus mean, indicators and class weighting should have evidence. Compare one-hot with ordinal encoding only when appropriate; ordinal encoding imposes artificial order on nominal categories. Scaling is usually useful for linear/distance models. Use log1p only where values > -1 and interpretation is defensible. No automatic outlier removal or correlation-based feature deletion.
- **Features and dependence:** Record selected columns and explicit reasons for exclusions. Consider entity IDs, duplicate records, timestamp ordering, target proxies and information unavailable at prediction time. Do not use shuffled CV for repeated entities or temporal forecasting. Group/time columns are excluded as predictors by the bundled runner. Time gaps count distinct timestamps, not rows or calendar days. For more complex embargoes, extend and test the splitter before development.
- **Two classifiers:** Choose a meaningful contrast, with data size, expected nonlinearity, interpretability and compute cost in mind. The six available families are logistic regression, random forest, extra trees, decision tree, KNN and Gaussian Naive Bayes. They are options, not a requirement to use a specific pair. Gaussian NB has a distributional assumption; one-hot KNN and high-dimensional dense models can be unsuitable.
- **Validation and tuning:** The bundled runner uses nested CV with shared folds. Inner CV selects hyperparameters; outer folds estimate development performance; a final inner search determines the full-training fitted artifact. Fold SD is descriptive variability, not a confidence interval. With time CV the initial training window has no OOF predictions; report OOF coverage. Declared sensitivity selection still adds selection optimism.
- **Sensitivity:** Use only for a material uncertainty. Empty `sensitivities` is valid with a recorded explanation. Alternative configurations run against the same folds and labels. Select one complete variant before locking. Do not choose sensitivities after viewing test results or combine fragments of variants without another train-only experiment.
- **Stopping:** Bound grids and folds before running; convergence warnings fail the run. Fix inadequate iterations or incompatible settings using training evidence. Other warnings are saved and must be reviewed. Do not claim model superiority from a small difference relative to fold variability.
