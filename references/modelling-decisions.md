# Dataset-specific decisions

For each material item record observation, decision, rationale and human-review point before fitting. Dataset paths and column names convey no reliable business semantics. The plan chooses candidates for empirical comparison, not a winner before evaluation.

- **Target and metrics:** A user-supplied target takes precedence, followed by authoritative metadata. When neither exists, follow the preflight's training-only ranked heuristic and use its highest-ranked classification-compatible candidate unless visible task context contradicts it. Record every candidate, score component, tie-breaker, alternatives and a human-review point. This predicts the target column; it does not confirm task or label semantics. Ask only when there is no compatible candidate or a contradiction. Do not infer meaning from class names alone. Choose the primary metric **before fitting** from task objective, class balance, known error costs, binary/multiclass setting and whether ranking, hard labels or probability quality matters. Record Observation → Metric → Rationale; it governs inner-CV tuning and the prespecified comparison. Secondary metrics interpret the error profile rather than replace the primary after seeing results. Preserve labels as strings (including numeric-looking labels). Macro metrics help multiclass/minority visibility; binary precision/recall/F1 suit corresponding error trade-offs; accuracy, average precision or log loss need their own justification. Average precision is not trapezoidal PR-AUC. Unknown costs are a limitation. Undefined metrics receive null with a reason, not invented zeroes.
- **Decision basis:** Mark each material choice as an invariant methodological rule, dataset-specific evidence, user/domain constraint, conventional default or unknown. A default used because semantics or costs are unavailable is a baseline, not an operational optimum. Storage dtype is evidence about representation, not proof of feature meaning; numeric-coded categories need review.
- **Imbalance:** Diagnose prevalence and minority counts, but do not select balanced accuracy, class weights or resampling from imbalance alone. Consider objective, positive-class meaning, FP/FN costs, fold feasibility and calibration. Record an explicit per-model no-weight/fixed-weight/tuned-weight decision. Resampling is outside the bundled runner and requires a fold-local tested extension rather than preprocessing the full dataset.
- **Preprocessing:** Use training-specific evidence: missingness pattern, measured scale/range, saved distribution diagnostics, model scaling needs, categorical cardinality/sparsity, leakage risk and uncertain feature semantics. The diagnosis records sample skewness with a declared material threshold, sample excess kurtosis as a tail-weight signal, and Tukey 1.5 x IQR counts as potential statistical outliers. These are different observations: skewness does not prove heavy tails, high excess kurtosis is descriptive rather than distributional proof, and an IQR flag does not establish an error. Cite the actual metric/column behind a material decision; never use vague language such as "tails differ". Choose allowed imputation, encoding, scaling, transformation and indicators per model; do not apply one fixed recipe. Fit learned steps inside each training fold. Ordinal encoding imposes artificial order on nominal categories; log1p needs values > -1 and an interpretable reason. No automatic outlier removal or correlation-based deletion. Record Observation → Decision → Rationale → Human-review point for each material choice.
- **Features and dependence:** Record selected columns and explicit reasons for exclusions. Feature selection/engineering is optional: if no supported transformation is needed, say so rather than inventing one. A potential statistical outlier is not evidence to delete it; first consider data-entry validity, legitimate rare cases and domain bounds. Consider entity IDs, duplicate records, timestamp ordering, target proxies and information unavailable at prediction time; association alone does not establish leakage. Do not use shuffled CV for repeated entities or temporal forecasting. Group/time columns are excluded as predictors by the bundled runner. Time gaps count distinct timestamps, not rows or calendar days. For more complex embargoes, extend and test the splitter before development.
- **Model count and contrast:** Choose two complementary classifiers by default. Add a third only if the diagnosis motivates a distinct question that the first pair cannot address, within the compute and two-page report budget. This is a skill design choice, not a Variant 2 mandate. Record the available-registry snapshot, shortlist basis, considered alternatives and why the count is sufficient. For each candidate record Observation → Selected classifier → Rationale → Expected strength → Known limitation → Human-review point, plus a grid rationale and stopping rule. Discuss only materially relevant dimensions such as sample size, feature types/dimensionality, imbalance, plausible nonlinearity/interactions, outliers, interpretability, dependence and compute. The seven available families are logistic regression, random forest, extra trees, decision tree, KNN, Gaussian Naive Bayes and a probability-enabled support vector classifier; this is an implementation registry, not a claim that the shortlist is globally optimal.
- **SVM boundary:** Consider SVM when scaled numeric/encoded features and a margin-based boundary are plausible. Scaling is mandatory. The runner wraps SVC in fold-local probability calibration for the shared scorer, adding work beyond the explicit search fit count. Before any model fit, it verifies the required per-class count for the largest declared `calibration_cv` across every outer-inner, outer-refit, final-inner and full-refit training subset; infeasibility stops the run with the failing subset and counts. This implementation allows SVM only with stratified CV; grouped/time-aware calibration requires a tested extension before use. Nonlinear kernels receive a conservative pairwise-kernel memory guard; large datasets should prefer a justified linear kernel or an explicitly implemented scalable approximation. Bound `C`, kernel and `gamma` choices before fitting. SVM absence or rejection for compute reasons is not evidence of statistical unsuitability.
- **Fixed parameters:** For every estimator value placed in `params`, answer separately (1) why the parameter was not tuned and (2) where the exact fixed value came from and why that value was chosen. Compute budget can answer the first question without answering the second. Schema v6 requires explicit treatment of `max_iter`, ensemble `n_estimators`, and SVM `calibration_cv`, which older runners silently imposed. Record the exact-value source from the schema vocabulary; if it is unavailable, use `unknown` with a null rationale rather than reconstructing a plausible story after fitting. Deterministic seed, single-job execution and SVM cache allocation are recorded separately as runner controls. Do not require every parameter to be tuned: convergence safeguards, implementation constraints, authoritative requirements and deliberately retained defaults can remain fixed when their provenance is explicit.
- **Validation and tuning:** Nested CV is this skill's methodology, not an explicit course requirement. Inner CV selects hyperparameters/configurations; outer folds evaluate the tuned procedure. Preserve every candidate's inner-fold scores, mean, variability and rank for each outer search and the final full-training search. Outer scores do not justify expanding grids, changing family/preprocessing/primary metric and then claiming the same outer estimate is independent. Such redesign is a new development iteration with its own selection uncertainty. The final inner search determines the full-training artifact; record its split seed, selected parameters and full-data refit row count. Prespecify bounded grids and fit budget; tuning stops after the inner search is exhausted, not when an arbitrary score is reached. In a two-value numeric grid, every selection is necessarily an endpoint; report coarse coverage and do not interpret it as evidence beyond the range. Only an edge selected after one or more interior candidates were evaluated supports an untested-direction question for a future independent run, and even then it does not authorize automatic expansion. Fold SD is descriptive, not a confidence interval. With time CV report OOF coverage. Sensitivity results are interpretive only and never select the locked configuration.
- **Threshold policy:** For binary work, choose fixed, tuned or model-default behavior before development. A fixed value needs separate exact-value provenance and a reason it was not tuned. A tuned value needs a predeclared threshold-dependent objective and joint inner-CV-only search; save selections for every outer fold and the final refit. A model-default decision needs an explicit rationale. Threshold sensitivity is not optimization, and held-out data never select a threshold.
- **CV and compute:** Choose fold counts and strategy from class counts, sample size, dependence, temporal ordering and available compute. Unknown dependence stays a limitation. Record the explicit-fit ceiling and its source; do not treat the packaged ceiling or fixture folds as universal defaults. Internal calibration and estimator work may exceed the explicit search-fit count.
- **Sensitivity:** Use only for a material uncertainty. Empty `sensitivities` is valid with a recorded explanation. Alternative configurations run against the same folds and labels as interpretive robustness evidence. They are not selection-eligible and cannot be locked, even if numerically better. If a result motivates adoption, create a new independent plan/run with that configuration as the baseline; do not combine fragments of variants or revise after held-out access.
- **Comparison and stopping:** Before fitting, declare the executable model-selection policy. It compares primary scores on shared outer splits with the correct direction, forms a practical-tie set using a dataset/task-specific predeclared tolerance, then applies lower outer-fold SD and the complete declared model order. A zero tolerance means only exact numerical ties; never invent a universal nonzero threshold. Development saves and verification recomputes the outcome, so later review prose cannot choose another family. Distinguish “numerically higher” from “meaningfully better”; the selected family's outer score is selection-conditional in a training-only report. Convergence warnings fail the run; fix settings only using training evidence. Other warnings require review. No automatic adaptive refinement is bundled.
